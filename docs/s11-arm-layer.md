# S1.1 · 手臂骨骼层

> 日期：2026-10-28
> 目标：让角色能挥手。原素材手插在裤兜里，做不了。
> 结论：**通过**。手臂成为可绕肩轴旋转的独立层，双击触发挥手。

---

## 一、三条路，前两条都撞墙

### ❌ 路线 A：切现有袖子来旋转

定稿的袖子是垂在身侧的宽松袖，和躯干之间有黑描边分隔，看起来能切。

放大到 4x 才发现不行：**袖子下缘和衣摆互相遮挡**。袖子旋起来后，原位置会露出
一块原图根本没画的区域——那里是"袖子后面的身体"，画师没画，补不出来。
镜像也没用，因为左右袖把两侧身体都遮住了。

### ❌ 路线 B：重新生成一张「抬手」的整图

用同一套 FaceID 参数（p1.jpg / weight 0.75）跑 9 张不同姿势，全部失败：

| 项 | 结果 |
|---|---|
| 脸（五官） | 一致 ✅ |
| 发型轮廓 | **变了** ❌ |
| 头身比 | **变了** ❌ |
| 衣服款式 | **变了**（圆领变 V 领） ❌ |

**关键教训：IPAdapter FaceID 只锁五官，不锁整体形象。** 它把脸放进去了，
但发型剪影、脖子长度、肩宽、衣服版型全由提示词和随机种子重新决定。
想锁整体形象得靠 LoRA 微调或 reference-only，不是 FaceID 能解决的。

顺带一个有价值的副产品：两张图的骨架几何几乎完全重合（身高差 0.2%、
颈线相对位置差 0.3%、髋部中心差 1px）。因为同样的 `chibi, full body,
white background` 构图提示词会让 SDXL 把角色放在画布的同一位置。
**姿势变体不需要复杂配准**——这个结论对后续做动作库有用。

### ✅ 路线 C：在定稿图上 inpaint 手臂

蒙版外一个像素都不动，脸和衣服 100% 保持。s123 这张一次成功：

- 蒙版只覆盖右袖 + 右上方的举手空间（6.0% 画布）
- 蒙版必须向上留出空间，否则手臂画到一半被截断
- 蒙版不能碰头部，否则脸被重绘

对比之前做表情层失败的 inpaint：那次是眼睛（58px 半径 → latent 里 7px），
SDXL 的 1/8 latent 分辨率做不了这么小的区域。手臂区域大 30 倍，一次就成。

## 二、球关节：为什么臂层要带一块圆

手臂绕肩旋转时，臂根与躯干之间必然裂开一条缝。纸片人骨骼动画的标准解是
让臂层多带一块**以旋转轴为圆心的圆形像素**——转的时候圆跟着转，缝始终被盖住。

```
ARM_POLY（沿描边读出的轮廓）+ circle(PIVOT, r=46)
```

坐标是逐点读 4x 放大网格图得到的，不是估的。第一版多边形凭感觉写，
结果只切出手掌、袖子整块丢了。

多边形是直线连的，而手掌和袖口都是圆弧，所以还要 `dilate(17)` 往外扩——
背景 alpha=0，多包进来画不出来。但**不能往躯干方向扩**，否则臂层会带进
一块衣摆，边缘被切成直边白肉。

## 三、三套素材，两个状态

| 文件 | 用途 |
|---|---|
| `body.png` | idle 的身体（定稿原样，手插兜） |
| `body_wave.png` | 挥手的身体（右臂被挖掉，原位补成衣摆） |
| `arm_r.png` | 手臂（袖子 + 手 + 肩部圆补丁） |

`body_wave` 必须来自 inpaint 图而不是定稿：定稿里那块是垂下的袖子，
挖掉就是透明洞；inpaint 图里 AI 已经把它补成了完整衣摆。

**z-order：`legs → body → arm → head → collar`**

手臂不能放最上层——臂根那块被裁成直边的白肉会露在外面。放 head 之后
就没事，因为手掌在头右侧、不与脸重叠，被 head 盖住没有副作用。

## 四、顺手修掉一个藏了很久的 bug：颜色通道反了

做这一层时发现肤色发蓝。查下来：`cutout_bg()` 返回的是 **cv2 的 BGRA**，
但保存时用了 `Image.fromarray(arr)`，**PIL 把它当 RGBA 存** —— 红蓝通道互换。

```
原图肤色 (204,164,161)  →  层文件 (161,164,204)
```

这个 bug 从 S0.7 切层就带进来了，影响 head / body / legs / collar / 全部
expr_*.png，也就是说**之前所有渲染出来的画面颜色都是错的**（偏冷）。
表情层脚本里硬编码的肤色常量 `[222,243,255]` 就是照着错误通道取的，一并修正为
`[255,243,222]`。

修复：所有落盘改用 `cv2.imwrite`（它正确处理 BGRA），表情层重跑。

## 五、抬手和收手：演不出来，就淡化

臂层只有「举起」这一个姿态，**没有「垂下」**。试过往下转：+35° 手臂开始
水平外伸，+48° 袖根与衣摆互相穿插，+60° 直接扎进躯干。这个 rig 转不出垂手。

也就是说「抬手」和「收手」两个动作都没有对应的中间姿态可插值。第一版直接硬切：
2.6s 到点，一帧之内手臂消失、身体从「无右臂版」跳回「插兜版」。实测那一帧的
位移差超过 100px，看起来像瞬移。

解法是**交叉淡化**，不是补帧：

```
mix = min(1, 已过时间/220ms, 剩余时间/220ms)
body：先铺 body_wave（全不透明）→ 再叠 body，透明度 (1-mix)
手臂：透明度 mix
```

之所以敢直接叠两层 body，是因为 **`body.png` 和 `body_wave.png` 只有右臂那一片
像素不同**（inpaint 只改了蒙版内），其余完全一致。同一批像素自叠不会有任何变化，
所以重影只可能出现在手臂那一片——那正是我们要过渡的地方。

实测淡入 0→0.23→0.69→1.00、淡出 1.00→0.45→0.00，各约 220ms（30fps 下 6~7 帧）。
收手的最后一帧 mix=0，此时 `body_wave + body@1.0` 与原 body 逐像素一致，
所以「挥手结束」这个切换点是连续、无跳变的。

> 淡化只在挥手首尾 220ms 生效，中段 `mix == 1.0` 时走的是短路分支
> （`if (mix < 0.999)`），不额外合成一层，开销为零。

## 六、实测

| 场景 | CPU | 内存 |
|---|---|---|
| 空闲 | **0.29%** | 56.8MB |
| 挥手（2.6s 满帧 + 首尾淡化） | 1.14% | 56.8MB |
| 抛掷 + 落地 | 0.98% | 57.1MB |

手臂层让包围盒高度增加 16px，宽度不变（手臂本来就在角色宽度内），
窗口仍是 202×267，空闲开销与 S1.0 持平。内存从 55.2MB 涨到 56.8MB，
是多了 `arm_r.png`（626KB）与 `body_wave.png`（97KB）两张贴图。

## 七、交互

| 操作 | 动作 |
|---|---|
| 单击 | 跳一下 |
| **双击** | **挥手（2.6s，1.6Hz 摆动，±11°）** |
| 按住拖动 | 拎起来 |
| 甩出 | 抛掷 → 落地回弹 |

双击的事件序列是 `press → release → dblclick → release`，中间那一按已经触发了
跳跃，所以真实表现是**蹦一下再挥手**。这是有意保留的：去掉它就得把单击响应延迟
150ms 等双击判定，那种迟滞比多跳一下难受得多。

## 八、已知缺口

| 项 | 状态 |
|---|---|
| 抬手/收手靠淡化，不是真动作 | 已从「硬切跳变」改善为「220ms 交叉淡化」，见第五节 |
| 只有右臂 | 左臂没做（素材只有一只手插兜，另一只没露出来） |
| 手臂不能跟头部旋转联动 | 头转 ±12° 时手臂不动，正常姿态下没问题 |
| 从「举起」转到「垂下」不可用 | 超过 +25° 手臂会插进身体，所以 idle 用的是另一套 body |

## 九、复现

脚本都在 `~/AI/`（含人脸素材，不入库）：

```bash
python3 gen_arm_inpaint.py      # 在定稿上 inpaint 出手臂，4 个种子
python3 build_arm_layers.py     # 切 arm_r.png / body_wave.png
python3 make_expr4.py           # 重跑表情层（通道修复后必须重跑）
```

渲染验证：

```bash
./run.sh --wave                  # 启动 0.6s 后自动挥一次
./build/bin/desktop --test-dbl --trace   # 合成双击，验证「跳 + 挥手」全链路
./build/bin/desktop --snapshot out.png --snap-arm -18 --snap-expr happy
```
