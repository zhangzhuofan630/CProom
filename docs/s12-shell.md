# S1.2 · 托盘、位置记忆、单实例、开机自启

> 日期：2026-10-30
> 目标：把它从「一个能跑的程序」变成「桌面上常住的东西」。
> 结论：**通过**。关掉现在有入口了，位置会记住，重复启动不会叠出两只。

---

## 一、为什么这步比再加一个动作更急

在这之前想关掉桌宠只有一条路：开终端 `pkill`。

这不是「不够完善」，是**根本没法交付**——给女朋友装的东西，她不会为了关一只桌宠
去开终端。所以哪怕动作库还很薄，也得先把这几个出入口补齐：

| 缺什么 | 后果 |
|---|---|
| 没有退出入口 | 只能 `pkill` |
| 不记位置 | 每次开机都弹回右下角，得重新摆 |
| 没有单实例 | 手滑点两下就两只叠在一起，还分不清哪只是哪只 |
| 没有自启 | 每次开机要手动启动一次 |

## 二、托盘菜单

```
挥挥手
隐藏 / 显示
回到右下角
─────────
开机自启  [ ]
─────────
退出
```

三个设计决定：

**1. 「挥挥手」必须单独列一项。** 双击虽然能触发，但没人猜得到。桌宠这点表现力，
藏在一个没人知道的手势里等于没有。

**2. 「隐藏」而不是「关闭」。** 桌宠不是普通窗口，它常驻是常态。真正的退出
单独一项放最下面，和常见托盘应用一致。

**3. 关窗＝收进托盘。** 为此要同时做两件事：`setQuitOnLastWindowClosed(false)`，
以及在 `closeEvent` 里 `ignore()` 之后 `hide()`。少做一样都会出现「点一下 X 就没了」。

> 顺带一个必须的配套：**隐藏时必须停掉定时器**。窗口隐藏后不再 paint，但 `tick()`
> 照跑——物理积分、呼吸、跟随光标全在算，纯粹空转。不加这一条，隐藏状态下依然
> 占着与显示时一样的 CPU，只是没人看得见。

## 三、托盘图标：不单独出资源

图标由 petpack 的 `head` 层实时生成，一次给 16/22/24/32/48/64 五个尺寸。

这样做的理由很实际：**托盘图标只有 22px**，把 200px 的整个人缩下去会糊成一团色块，
头部剪影反而好认。而且换角色时图标自动跟着换，不必再维护一套图标文件。

## 四、位置记忆

存 `QSettings`（Linux 上是 `~/.config/desktoppet/Desktoppet.conf`）。

**存盘时机**：拖动松手 / 落地静止时（`settled` 信号），加 `aboutToQuit` 兜底。
不在拖动过程中存——那样会变成每帧写一次配置文件。

**恢复时必须校验**：

- 坐标不在任何屏幕内（拔了外接屏、改了分辨率）→ 丢掉，回右下角。
  宁可回到默认位置，也不能让窗口飘在看不见的地方——那样用户除了 `pkill`
  同样没有任何办法。
- 坐标在地面之上（退出那一刻正好在飞）→ 恢复后让它自己掉下来。
  不置 `m_airborne` 的话**它会永远悬在半空**，因为物理只在空中状态才跑。

### 顺带修掉一个 4px 的旧偏差

算地面时窗口会比屏幕高 4px（`kPadBottom` 让内容底边贴着屏幕底时，窗口本身探出去
4px），窗管把它顶回来，于是 Qt 认为在 817、X 上实际在 813。

以前只影响观感（差 4px 看不出来），加了位置记忆之后它变成**每轮存取漂 4px**：
存 817、恢复成 813、下次再存 813……而且拖拽的边界计算和实际位置用的不是同一个值。

修法是在 `updateGround()` 里跟着夹一次物理屏幕边界：

```
ground = min(可用区底 - 窗口高 + kPadBottom,  屏幕底 - 窗口高)
```

## 五、单实例

`QLockFile` 放在 `XDG_RUNTIME_DIR`（回退临时目录）。

两个细节：

- **测试模式不拿锁**。`--bench` / `--snapshot` / `--test-tray` 各跑各的，
  否则回归脚本一并发就互相挡住。（第一版没区分，第二次 bench 直接被拦。）
- **锁文件残留不要紧**。`QLockFile` 里存了 pid，进程被杀掉后下次启动会发现
  pid 已死，自动接管。实测 `pkill` 之后立刻重启正常。

## 六、开机自启

Linux 写 `~/.config/autostart/desktoppet.desktop`，Windows 写
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。

**踩了一个必须记的坑**：第一版是「把当前命令行原样写进自启项，剔掉几个一次性参数」
（黑名单）。结果从 `--set-autostart on` 这个命令本身创建自启项时，把
`"--set-autostart" "on"` 也写了进去——那条命令开机后设完自启就退出，
**桌宠永远起不来**。

改成**白名单**：只保留 `-p/--pack`、`-w/--width`、`-f/--fps`、`--idle-fps`。
白名单的失效方式是「少带一个参数」（退回默认值），不会产生错误行为。

Wayland 会话下自启项会自动加 `env QT_QPA_PLATFORM=xcb`——开机自启不走 `run.sh`，
没人替它补这个变量，而原生 Wayland 下窗口无法置顶。

另外给了个 CLI 入口，方便脚本和排查：

```bash
./build/bin/desktop --set-autostart on|off|status
```

## 七、实测

| 场景 | CPU | 内存 |
|---|---|---|
| 空闲（显示中） | **0.30~0.44%** | 56.3MB |
| 拖拽抛掷 | 1.00% | 56.7MB |

托盘 / QSettings / QLockFile 都是事件驱动的，空闲开销与 S1.1 持平。

### 托盘自测（`--test-tray`）

没有鼠标可用，所以按真实路径依次触发每个菜单动作：

```
[tray] 已挂上托盘图标
菜单项: 挥挥手 / 隐藏 / 回到右下角 / 开机自启 [ ] / 退出
初始     geo=(1658,813)
回右下角  geo=(1658,813)
挥手后   visible=1
隐藏后   visible=0
再显示   visible=1
自启: before=0 flipped=1 restored=0 => OK
位置存取: 写入=(994,553) 读回=(994,553) => OK
```

另外单独验过：

- 屏幕外坐标（`99999,99999`）→ 回落到右下角 ✅
- 半空坐标（`900,400`）→ 恢复后自己掉到地面并弹一下 ✅
- 进程被杀后立刻重启 → 不会被残留锁挡住 ✅
- `DESKTOPPET_NO_TRAY=1` → 走「无托盘」降级，关窗即退出 ✅

