# S1.0 · 拖拽与落地物理

> 日期：2026-10-28
> 目标：让桌宠能被拎起来、甩出去、落到任务栏上弹一下。
> 结论：**通过**。交互全链路可用，空闲开销零退化（0.33%，与 S0.9 一致）。

---

## 一、为什么先做这个

S0.9 之后桌宠会眨眼、会转头、会跳，但**用户碰不到它**——只能看。桌宠和「会动的贴纸」
之间的差别不在动画数量，在于它是不是个能被摆弄的东西。这是 Phase 1 之前必须补的一课。

按价值排序，拖拽排在手臂层、animations JSON 化、Wayland 原生后端之前。

## 二、设计决策

### 2.1 一套积分，不是两套动画系统

跳跃和拖拽落体跑的是同一个 `stepPhysics(dt)`：

| 动作 | 实现 |
|---|---|
| 点一下 | `velY = -430`，然后交给重力 |
| 甩出去 | 松手时把拖动速度交给同一个物理体 |
| 落地回弹 | `velY > 620` 时 `velY = -velY * 0.30` |
| 落地压扁 | 触地瞬间 `squash = 1`，按 `e^{-9t}` 衰减 |

好处是没有「跳跃动画」这种需要单独维护、单独调试、单独对齐的东西。改重力，
跳跃高度和落体手感一起变，不会出现「跳得很轻但摔得很重」的割裂。

### 2.2 位置存 `qreal`，窗口坐标只是投影

早期 `m_jumpY` 是「跳跃偏移量」，站立位置另存 `m_basePos`。加拖拽后这个模型撑不住了：
拖拽会改变「站立位置」本身，而且拖动时每帧位移经常不足 1px，用整数位置会反复取整，
慢速拖动看起来像卡帧。

改成 `m_posX/m_posY`（qreal）是唯一的位置真相，`move()` 时才取整：

```cpp
const int ix = qRound(m_posX);
const int iy = qRound(m_posY);
if (ix != m_appliedX || iy != m_appliedY) {   // 只在跨过整像素时 move
    m_appliedX = ix;  m_appliedY = iy;
    move(ix, iy);
}
```

一次跳跃约 13 次窗口移动，不是每帧都动。

### 2.3 空中阻尼 ≠ 地面摩擦

第一版两处都用空气阻尼 `kAirDragX = 1.8`（时间常数 0.55s）。实测甩一下，
桌宠在屏幕上**滑了 3.5 秒才停**——看着像踩着冰。

改成：

| 状态 | 系数 | 时间常数 |
|---|---|---|
| 空中 | 1.8 /s | 0.55s |
| 地面 | 14 /s | 70ms |
| 触地瞬间 | `velX *= 0.5` | 一次性吃掉一半 |

再加一条截断：落地后 `|velX| < 20 px/s` 直接归零。指数衰减永远逼近但不到零，
不截断的话它会为了最后 1px 的位移继续满帧重绘好几秒。

实测：落地后 **0.15s 内**横向速度归零。

### 2.4 拖动必须钳在屏幕内

这是个真 bug，合成拖拽测试第一版就暴露了：拖动时不钳边界，可以把桌宠拖到屏幕外面，
松手后窗口被硬钳回来——但如果没有那层钳制，窗口就飘在屏幕外，**用户再也点不到它**。

现在拖动时：

```cpp
nx = qBound(avail.left(), rawX, maxX);        // 水平：可用区宽度 - 窗口宽
ny = qBound(avail.top(),  rawY, m_groundY);   // 垂直：屏幕顶 ~ 地面
```

还有个细节：**速度必须用钳制后的位移算**。贴着边拖的时候，原始位移一直在增长，
松手会弹射出去；用钳制后的位移算，贴边拖动速度自然为 0。

### 2.5 拖动阈值要跟「按下点」比，不能跟窗口当前位置比

```cpp
// ❌ 错的：慢速拖动时每帧只差 1px，永远超不过阈值，会被判成点击
if (qAbs(nx - m_posX) > kDragThreshold) m_dragMoved = true;

// ✅ 对的：跟按下时的鼠标全局位置比
if (qAbs(gp.x() - m_pressGlobal.x()) <= kDragThreshold && ...) return;
```

死区内窗口**完全不动**，避免手抖把桌宠挪走 4px。超过 4px 才开始跟随。

### 2.6 拎在半空时禁止转头

`updateFollowTarget()` 开头直接 `if (m_dragging) return;`。手是把它吊起来的，
头还跟着光标转会显得「断线」。松手后恢复。

## 三、实测（合成拖拽，无头环境）

因为没有 xdotool，加了一个 `--test-drag`：进程内合成 `MouseButtonPress` /
`MouseMove` / `MouseButtonRelease` 事件直接 `QApplication::sendEvent()`，
走的是和真鼠标**完全相同**的代码路径。

```bash
QT_QPA_PLATFORM=offscreen ./build/bin/desktop --test-drag --trace --bench 4
```

轨迹（步骤间隔 16ms，向上再向下的抛物线，向左甩）：

| t | pos | vel | 状态 |
|---|---|---|---|
| 0.43s | (527, 511) | — | drag=1 按下并越过死区 |
| 0.53s | (462, 378) | (-675, -1212) | drag=1 跟手 |
| 0.63s | (386, 344) | (-671, +55) | drag=1 到达顶点 |
| 0.73s | (321, 437) | (-682, +1168) | drag=1 向下 |
| 0.83s | (255, 537) | (-304, -472) | **drag=0** 松手后第 2 帧触地，squash 0.64 |
| 1.33s | (154, 537) | (-34, 0) | 二次触地，停下，squash 0.22 |
| 1.63s | (154, 537) | (0, 0) | squash 衰减到 0.01 以下 |

关键点：**触地速度 450 < 620，不弹**；从更高处摔才会弹。分级是对的。

## 四、性能回归（xcb 真实后端）

| 场景 | CPU | 内存 | 帧率 |
|---|---|---|---|
| 空闲 | **0.33%** | 54.9MB | 8 |
| 跟随光标 | 0.80% | 55.1MB | 10.3 |
| 持续摆动（上界） | 1.37% | 55.2MB | 19.3 |
| 抛掷 + 落地 | 0.51% | 55.3MB | 11.3 |

空闲与 S0.9 **完全一致**——物理和位置更新是零成本，因为静止时 `move()` 不触发，
`stepPhysics` 只做几次比较。

`stepPhysics` 每帧调一次 `updateGround()`（查询 QScreen），静态时 8fps 下这点开销
测不出来，暂时不缓存。

## 五、未验证 / 已知缺口

| 项 | 状态 |
|---|---|
| 真实鼠标拖拽手感 | ⚠️ **只测了合成事件**，需要用户在 KDE 上实际拖一次 |
| 多显示器 | ❌ 未测。`currentAvail()` 用 `windowHandle()->screen()`，跨屏拖动时是否及时更新未知 |
| DPI 缩放（150% / 200%） | ❌ 未测 |
| 拖出屏幕顶边 | 已钳制，但「拖到顶边后松手」的落体距离很长，手感待观察 |
| 甩出速度上限 | 2400 px/s，一次快速挥手会被限。可能需要调 |

   换形象就不能调。
